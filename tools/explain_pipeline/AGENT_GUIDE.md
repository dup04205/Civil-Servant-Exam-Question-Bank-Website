# 시험지 1종 해설 작성 지침 (작업자용)

입력: `work/papers/{PID}.json` — 문항별 `stem`, `passage`, `bogi`(보기 ㄱ·ㄴ·ㄷ), `choices`, `answer`(공식 정답), `polarity`,
`formulas`, `has_image`, `needs_rewrite`, `existing`(현재 해설).
출력: `work/verified/{PID}.json` 하나. 작성 후 반드시 `python3 validate.py {TASK} {PID}` 가 `OK`가 될 때까지 고친다.

## 출력 스키마
```json
{"PID-Q3": {
  "overall_commentary": "출제 영역: {과목} · {핵심 주제}\n정답은 ②이다. {핵심 결론과 근거 요약}",
  "choices": {"1": "...", "2": "...", "3": "...", "4": "..."},
  "bogi": {"ㄱ": {"ox": "O", "text": "..."}, "ㄴ": {"ox": "X", "text": "..."}}
}}
```
- TASK=`full`: `needs_rewrite`가 true인 문항은 overall_commentary와 choices 전부를 새로 쓴다. false인 문항은 overall·choices를 넣지 않는다(기존 유지).
  보기(`bogi`)가 있는 문항은 needs_rewrite와 관계없이 bogi를 반드시 쓴다.
- TASK=`bogi`: 보기가 있는 문항만, `bogi` 키만 넣는다. 기존 선지 해설(`existing`)과 결론이 맞아야 한다.
- 문항 ID 키는 입력의 `id` 그대로. 정답은 입력의 `answer`가 공식 정답이며 절대 바꾸지 않는다.
  overall에 `정답은 ②이다.`처럼 원문자로 공식 정답을 적는다. 해설 결론이 공식 정답과 어긋나면 내 판단이 틀린 것이니 다시 검토한다.
- `ox`: 보기 내용 자체가 옳으면 O, 틀리면 X (발문이 "옳지 않은 것"이어도 내용 기준). `[O]`·`(정답)` 표시는 스크립트가 붙인다.

## 문체·내용 규칙
- 시중 기출해설집 수준의 문어체: `~이다.`, `~한다.`, `~하므로 옳지 않다.`, `따라서 옳은 설명이다.`
- 각 선지·보기마다 왜 옳은지/틀린지 구체 근거를 쓴다. 틀린 선지는 무엇이 틀렸고 바른 내용이 무엇인지 적는다.
- 법령 문항: 조·항·호·목과 판례 사건번호(예: 대법원 2004. 5. 14. 선고 2004도74 판결, 헌법재판소 2015. 9. 24. 2012헌바410 결정)를 명시하고
  `./law.sh`로 조문 본문과 사건번호를 실제로 확인한다. 확인 못 한 사건번호는 쓰지 말고 법리만 쓴다.
- 비법령 문항(공학·자연과학·경제 등): 정의·공식·계산 과정을 구체적으로 쓴다. 계산 문항은 식과 수치를 단계별로 제시한다.
- 그림(`has_image`)은 저장소에 없다. 텍스트·수식·선지·정답으로 풀 수 있는 만큼만 설명하고, 그림의 구체 수치를 지어내지 않는다.
  ("그림의 구조에서 …" 처럼 일반화해 서술).
- 금지: "관련 이론·법리에 부합한다", "제시된 요건과 결론이 타당하므로 옳다", "내용과 일치하므로 옳다" 같은 공허한 문구,
  본문 앞 `[O]`/`[X]`/`(정답)` 태그, 개발 용어(MCP, MST, 법령ID, DB, SQLite).
